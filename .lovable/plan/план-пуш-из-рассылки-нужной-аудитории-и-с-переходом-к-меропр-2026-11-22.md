# План: пуш из рассылки — нужной аудитории и с переходом к мероприятию

## Что изменится для вас
- Пуш будет уходить той же аудитории, которую вы выбрали в рассылке, а не всем подписанным.
- Если в рассылке есть кнопка «Записаться на мероприятие», нажатие на пуш откроет в приложении карточку этого мероприятия. Там будет кнопка «Записаться» (для платных — «Забронировать»), и сработают все обычные проверки: доступ резидента, лимит мест, оплата.
- Кнопка-ссылка в рассылке: нажатие на пуш откроет эту ссылку. Если кнопок нет, откроется главная `/app`.
- В истории рассылки появится строка «Пуш: отправлено N из M подписанных».
- Перед отправкой будет видно, сколько людей из выбранной аудитории включили уведомления.

## Что не меняется
- Рассылка в Telegram, отправка в группу, `/telegram`, интенсив, Telegram-бот, оплата, правила записи.
- Push мастермайнда и ДЗ.

## Этапы
1. **Предпросмотр на тестовых данных** (`/app/preview/broadcast-push`): форма → кто получит → как выглядит пуш → нажатие открывает карточку мероприятия → «Записаться». Без отправки и без рабочей базы.
2. **Ревью серверной части**: подготовить для ревью новую отправку пуша, которая выбирает получателей по аудитории рассылки и для каждого получателя проверяет, имеет ли он доступ к мероприятию. Подписки, которые больше не действуют, будут удаляться. Миграция с откатом нужна только для поля «пуш отправлено» в истории рассылки.
3. **Запуск** — только после `APPROVE BREAKING broadcast-push`: деплой в КЭМП (`wfjvjvbjjxcgkaolkgdq`, не MIRA), тест на одной учётке («Дмитрий 116»), потом рабочая отправка.

## Риски
- Средний: неправильный выбор аудитории → пуш уйдёт не тем людям. Защита: тесты на каждую аудиторию и пробная отправка на одну учётку.
- Старые устройства получат новый формат уведомления после обновления приложения. Старый формат продолжит работать.

## Расход
Этап 1: около 3 кредитов (2–5). Этапы 2–3: около 4 кредитов (3–6), отдельное подтверждение.

## Технически
- Новая серверная функция `broadcast-push` принимает только `broadcastId`, проверяет, что отправляет основатель или админ, читает `audience` и `buttons` из `broadcast_messages` и выбирает тех же получателей, что и `send-broadcast`, вместе с их `push_subscriptions`. Отправка идёт по Web Push (VAPID).
- Адрес перехода: `book_event` → `/app/schedule?event=<id>`, `url` → ссылка, по умолчанию → `/app`. `sw.js` уже умеет открывать `data.url`, менять его не нужно.
- `WebScheduleView` по параметру `event` открывает карточку мероприятия.
- Unit-тесты: адрес перехода, выбор аудитории. SQL-регрессия: получатели по каждой аудитории.
