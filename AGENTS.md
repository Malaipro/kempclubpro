# Architecture rules

- Dispatch broadcast Web Push through a dedicated admin-authenticated KEMP-only Edge Function using stored audience/event access checks and atomic per-broadcast claims; a server-side switch stays off until a fixed-account delivery test passes, preventing accidental wide sends and retries.

- Keep recurring club-event acceptance on a development-only route using an injected in-memory calendar in the existing management form; production recurrence needs a separately reviewed atomic server save, while fixture moves retain immutable credit-week anchors.

- Keep resident reward-goal prototypes on development-only Preview routes with in-memory selections injected into an optional Home slot; this avoids persistence, purchases and changes to live Home.

- Scope the /app messenger theme through `.web-chat-theme` and semantic chat tokens; this keeps topic Chat and Nutrition consistent without recoloring unrelated pages.
- Render photo Home through the dedicated web-only `WebHomeView` and scope styles through `.web-home-theme`; this keeps Telegram and other web sections unchanged.
- Store Home tile imagery as separate imported images mapped by section; this keeps each subject correctly framed without coupling tile layout to a sprite grid.
- Scope non-Home /app screens and login through `.web-app-theme`, with explicit theme classes on portaled dialogs; semantic tokens style existing controls without modifying shared components or other routes.
- Process mastermind deadline pushes in a fixed-purpose scheduled Edge Function with service-only reminder claims keyed by task, deadline and reminder kind; this isolates recipient targeting and prevents repeat scheduled deliveries. Deadlines are calendar dates in Europe/Moscow.
- Scope web mastermind plans, tasks, reports and dashboards by explicitly selected group and track, with a separate unassigned legacy bucket; this prevents mixing two-month outcomes and preserves Telegram contracts.
- Expose scoped mastermind writes through public SECURITY INVOKER wrappers over protected functions in the unexposed mastermind_private schema; owner and active group membership checks preserve existing table access without exposed elevated functions.
- Keep attendance test fixtures behind a development-only route and inject their API into the real resident and founder views using a shared in-memory store; this verifies both roles without bypassing production auth or writing live data.
- Distinguish attendance-only inserts by their immediate self-mark timestamp and explicit free club training metadata in the notification function; this suppresses booking alerts without caller-controlled flags or disabling triggers.
- Deliver every participant notification through `supabase/functions/_shared/appNotify.ts` (bell row in `notifications` + Web Push with WebCrypto aes128gcm); npm:web-push payload encryption is not decryptable on iPhones under Deno, and one path keeps bell and push consistent.
- Resident attendance uses schedule_participants self/decision fields; status derives from attended_marked_at, never from attended alone, and protected fields change only via verified-founder-account-and-role-checked SECURITY DEFINER RPCs (attended defaults to false, so it cannot mean absence).
- Stage notification Edge releases under sql/notification-release, never supabase/functions until explicit production approval; this prevents automatic deployment during isolated development.
- Route unified broadcasts through a founder-authorized server orchestrator with server-derived audiences and persistent per-channel claims; this prevents client recipient tampering and duplicate retries.
- Paid club events keep holds/payments in `paid_bookings` + append-only `paid_booking_ledger`; a role-independent trigger lets `schedule_participants` rows exist on paid events only via a founder-verified booking, so legacy bot/service_role inserts cannot bypass payment. Staged under `sql/paid-bookings`, gated by `VITE_PAID_BOOKINGS_ENABLED`.
- Recurring free club trainings are saved only through the atomic `club_recurring_series_save` RPC. The private occurrence ledger owns the original Moscow date/week and survives schedule moves, deactivation or deletion, so retries and concurrent saves never recreate handled occurrences. Stage changes under `sql/club-recurring`; never apply them to a hosted project without separate approval.
- Resident training rewards live in the append-only `resident_reward_awards` ledger, written only by the founder-checked SECURITY DEFINER `founder_confirm_attendance`; per-training and per-week unique keys plus a per-(user, week) advisory lock keep retries and concurrent confirms duplicate-free, and corrections reverse entries instead of deleting history. Resident rating adds active ledger points on top of the intensive `leaderboard` without overwriting it; the weekly coin bonus uses the dedicated `resident_week_full` rule, never `training_attendance`. Club events with attendance or booking history are deactivated via `founder_cancel_event_web` instead of deletion so check-in history and credit weeks survive. Stage changes under `sql/resident-rewards`; never apply them to a hosted project without separate approval.
