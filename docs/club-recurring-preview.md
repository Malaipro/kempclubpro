# Повторяющиеся клубные события — Preview и production-путь

## Текущее состояние (после переноса PR #10 в ветку Lovable)

- Рабочая форма `ClubScheduleManagement` сохраняет серии бесплатных клубных
  тренировок через атомарные RPC `club_recurring_series_preview/save`;
  серверная реализация и изолированные PostgreSQL-проверки — в
  `sql/club-recurring/`, паспорт применённой миграции — в
  `sql/club-recurring/APPLIED-20261123150355.md`.
- Development-маршрут `/app/preview/club-recurring` сохранён для приёмки на
  in-memory календаре (фикстура `createClubScheduleFixture`): обновление
  страницы сбрасывает тест, обращений к базе нет. В fixture-режиме форма не
  вызывает production RPC.

## Источник Preview

Исходный development-only Preview находится в Lovable-коммите
`6c81b356b2e1ab979122b9fd75017837ec31ab6c`. Он проверил форму, недельный и месячный
предпросмотр, московское время, сохранение `week_anchor` при переносе и неизменность разового
платного сценария на локальном in-memory хранилище.

Preview сознательно не содержал SQL, серверной авторизации, транзакции, конкурентной
дедупликации и постоянной истории отменённых/перенесённых экземпляров. Эти гарантии
даёт серверная реализация PR #10; клиентская защита и тестовое хранилище не заменяют
гарантии базы.

- 60 локальных тестов прошли: `bun test src/components/schedule/clubRecurrence.test.ts src/components/web-app/residentCheckins.test.ts src/components/web-app/checkinsPreviewStore.test.ts src/components/web-app/paidBooking.test.ts`.

- Резидент без предварительной записи нажимает «Я был», видит ожидание и 0/3.

- Разовое платное мероприятие сохранено без повторения; настройки оплаты сохранились при редактировании.
- Runtime errors и обращения к удалённому Supabase отсутствовали.
