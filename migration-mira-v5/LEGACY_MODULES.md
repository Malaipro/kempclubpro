# LEGACY_MODULES.md (v4)

Что в схеме КЭМП является легаси и что имеет смысл **не переносить** в МИРА.
Ничего из перечисленного в v4 не удалено — решение за владельцем проекта.

## 1. Кириллические таблицы (дубли англоязычных)

| Таблица | Дублирует | Комментарий |
|---|---|---|
| `участники` | `profiles` | ранняя версия карточки участника |
| `аскезы_участников` | `ascetic_activities` | старый трекер аскез |
| `кэмп_активности` | `user_activities` | старый лог активностей |
| `тотемы_участников` | `user_totems` | старая привязка тотемов |

Имена требуют кавычек в каждом запросе, ломают кодогенерацию типов.
**Рекомендация для МИРА:** не переносить; если нужны исторические данные — импортировать
в англоязычные таблицы.

## 2. Дублирующие enum'ы

- `activity_type` и `activity_type_new` — вторая появилась при расширении списка, первая осталась.
- `user_role` и `app_role` — `has_role`/`is_admin` работают с `user_role`; `app_role` не используется.
- Подтипы `lecture_subtype`, `shram_subtype`, `training_subtype`, `zakal_subtype` — частично перекрываются.

**Рекомендация:** в МИРА оставить по одному enum на сущность (`activity_type_new` → переименовать
в `activity_type`, `app_role` не создавать).

## 3. Модули, специфичные для мужского формата КЭМП

| Модуль | Таблицы | Комментарий |
|---|---|---|
| Пирамида КЭМП | `pyramid_levels` + бакет `pyramid-materials` | методология КЭМП, в МИРА содержание другое |
| Тотемы | `totems`, `user_totems`, `тотемы_участников` | символика КЭМП |
| Аскезы | `ascetic_types`, `ascetic_activities`, `аскезы_участников` | переносится, но справочник надо пересобрать |
| Гонка героев | `hero_races` | разовое мероприятие |
| Crash-тесты | `crash_tests` | использовалось в одном потоке |
| Тактические сессии | `tactical_sessions` | формат КЭМП |

Структуру можно перенести (она пустая без reference data), но справочники —
`totems`, `ascetic_types`, `pyramid_levels`, `achievement_types` — заполнять заново.

## 4. Интеграции, требующие пересоздания (не переносятся «как есть»)

- Telegram-бот: **новый** бот, новый токен, новый webhook (`telegram-server/`).
- Bitrix24 (`bitrix-referral-webhook`) — использовался для старой воронки; в МИРА заявки
  идут в собственную CRM (`contact_submissions`), интеграцию можно не включать.
- Nodul / Zapier webhooks — legacy-каналы приёма заявок, заменены нативной формой.
- Podpislon (договоры) — отдельный договор с провайдером, свои ключи.
- Аналитика: Top.Mail.Ru и Яндекс.Метрика — **новые счётчики**, ID КЭМП не использовать.

## 5. Служебные таблицы, которые стоит завести пустыми

`admin_access_log`, `audit_log`, `role_audit_log`, `contact_rate_limit`,
`telegram_bot_logs`, `telegram_bot_sessions`, `admin_sessions` — переносится только
структура, данные КЭМП не мигрируют.

## 6. Устаревшие «шифрование» и маскирование

`encrypt_phone` / `decrypt_phone` — base64. См. `SECURITY_NOTES.md` §5.
`mask_*` функции во фронтенде не используются — в МИРА можно не создавать.
